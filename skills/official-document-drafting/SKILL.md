# 公文与单位材料

以用户的单位、对象、事实和用途为准，写清要报告什么、请求批准什么或要求谁做什么。高校、企业的日常材料按实际语境表达，不自动升格为党政部署，不堆政策套话。仅起草和导出，不自动发文、报送或改动宿主设置。

## 事实与文种

1. 先读 [事实核验](references/core-事实核验与防编造.md) 和 [政策边界](references/core-政策边界.md)，再按目的读取下表中的一个或少数文种参考。各参考含写法、要素和模板；示例的机构、数据、条文、日期不能变成当前任务的事实。
2. 保留“拟、预计、尚未核实、未获批准”等有意义的状态和不确定性。未知具体值留 `[待补充：…]`，用简短的正文外说明列出缺口；不能把缺失信息包装成正式可发版本。
3. 请示聚焦一个可批示事项，通常只主送一个有权限的直接上级。预算或政策依据未提供时不得补造来源。报告汇报情况，不夹带审批请求；材料混有请批事项时，说明处理方式，并分写报告和请示，或明确建议改文种，不能悄悄删掉用户的审批诉求。
4. 日期地点尚未确定的活动通知输出待补充稿；除非用户已明确决定，不擅自写“另行通知”、设报名截止日、指定联系人或承诺后续安排。会议纪要必须区分讨论意见、拟办建议和实际议定事项。
5. 仅在任务需要政策、最新事实或用户要求检索时，使用宿主现有检索能力核对原始来源、适用范围和日期。不要求额外技能、API、付费服务或固定域名；来源不足时保留缺口。

## 输出与 Word

默认在对话中交付用户要求的稿件；用户要求文件时使用当前任务交付目录，草稿和验证放任务工作目录，不写用户主目录。长材料可用 [起草要素表](assets/templates/draft-request.md)，不必为普通任务逐项问询。没有对应文种时参考 [通用骨架](references/fallback-template.md)，仍以实际用途为准。

需要 Word 时先读 [版式与导出](references/core-版式与导出.md)。如用户提供单位模板，以模板为准，可使用宿主文档工具；不要为了本导出器改变用户模板。无专用模板的正文稿可用本包零第三方运行依赖的 Python 3.11+ 导出器，所有路径相对技能目录：

```text
python -B src/scripts/generate_docx.py /任务目录/稿件.md -o /任务目录/稿件-v01.docx --doc-type 通知 --title-wrap off
```

导出器支持本包的 22 个文种（中文名或英文 ID）。`--show-font-plan` 可查配置，`--title-font`、`--heading-font`、`--subheading-font`、`--body-font` 可指定本机已合法安装的字体。不随包分发、下载或安装字体。字体不可用时选择可用替代字体并在交付说明中说明，不能声称版式完全等同原模板。

- 默认拒绝覆盖已有输出，重跑使用新文件名；用户已经要求更新同一成品时可用 `--overwrite`。即使允许覆盖，也拒绝覆盖输入稿或图片素材。输出扩展名必须是 `.docx`。
- 图片必须是与输入稿同目录或子目录中的 PNG/JPEG，本脚本不下载远程图片。复杂表格、公式、专用红头、盖章和完整版记交给单位模板或宿主文档工具。
- 本包提供便于校对的版式基线，`official-standard` 是上游配置 ID，**不是国标合规认证**。首页不显页码、固定行距与段距为上游模板约定，应按单位现行要求调整。
- 导出后渲染所有页并目视检查中文、分页、标题、落款和页码；不能以生成成功或 XML 可解析替代视觉验收。无法渲染时明确标为未完成版式验收，不夸大为可直接发文。
- 交付前将具体事实、数值、文种和行动要求逐项对回材料。资料留有缺口的文件须说明仍为待补充稿。
