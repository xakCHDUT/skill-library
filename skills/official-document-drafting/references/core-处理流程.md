# 处理流程

本文件在上游流程基础上简化为自包含 Codex 路线。

1. 判断发文主体、对象、目的、行文方向和真实授权。需要上级批准用请示；汇报情况用报告；部署或告知用通知；平行商洽用函；会议纪要只记录材料支持的议定事项。一般工作总结、讲话稿不必转成法定公文。
2. 从 SKILL.md 进入 references/文种-<文种>.md，依其中起草要点和模板检查必要信息。政策及事实边界见 references/core-政策边界.md 与 references/core-事实核验与防编造.md。
3. 对缺口区分：能留占位并形成有用草稿的，先写待补充稿；会改变权限、目的或事实结论的，指出歧义再推进不受影响的部分。不要用常识填机构、预算、日期、地点或审批结果。
4. 写清每段职责：背景回答为什么写；进展回答已经做到哪；问题回答困难在哪里；请示事项回答批什么；安排回答谁做什么和材料中已有的期限。不把报告里的审批诉求删掉后称任务完成，应说明分写方案并保留诉求。
5. 区分必备、常见、条件项、地方单位样式及上游项目自定义。主送、落款等按文种处理；联系人、版记和固定展开句数不对所有单位一刀切。图表和清单只有材料存在且有用时才添。
6. 用户只要正文则直接交付正文；要求文件则写到当前任务交付目录或用户指定路径。辅助材料放任务工作目录。默认不覆盖成稿，使用清楚的文件名和版本号。图片引用遵守导出器的输入同目录或子目录限制。
7. Word 导出按 references/core-版式与导出.md，校对所有页；涉及正式发文时交付可审核稿件及实际缺口，由具备权限的人员作发文审核。
